# 多用户多级目录文件系统设计文档

## 一、整体架构

### 1.1 设计目标
本文件系统是一个基于磁盘模拟的多用户多级目录文件系统，具备以下特性：
- 支持多用户访问和权限管理
- 多级目录结构（树形组织）
- 一级索引文件
- 成组链接法空闲空间管理
- 每块大小：4KB

### 1.2 系统架构图
```
┌─────────────────────────────────────────────────────────────┐
│                      文件系统接口层                          │
│  (文件创建/删除/读写/目录操作/权限管理)                       │
├─────────────────────────────────────────────────────────────┤
│                      目录管理层                              │
│  (多级目录树、dentry管理、路径解析)                          │
├─────────────────────────────────────────────────────────────┤
│                      索引节点层                              │
│  (inode管理、文件元数据、索引块管理)                          │
├─────────────────────────────────────────────────────────────┤
│                      数据块层                                │
│  (数据块分配/释放、成组链接法空闲管理)                        │
├─────────────────────────────────────────────────────────────┤
│                      超级块层                                │
│  (文件系统元信息、整体状态管理)                              │
└─────────────────────────────────────────────────────────────┘
```

## 二、核心数据结构

### 2.1 超级块 (Super Block)

**作用**：存储文件系统的整体元信息

| 字段 | 类型 | 大小(字节) | 说明 |
|------|------|-----------|------|
| magic | int | 4 | 文件系统魔数，用于标识 |
| block_size | int | 4 | 每块大小（4KB） |
| total_blocks | int | 4 | 总块数 |
| free_blocks | int | 4 | 空闲块数 |
| inode_count | int | 4 | inode总数 |
| free_inodes | int | 4 | 空闲inode数 |
| root_inode | int | 4 | 根目录inode号 |
| free_list_head | int | 4 | 空闲块链表头 |
| group_size | int | 4 | 成组链接法每组块数 |

**设计说明**：
- 超级块位于磁盘第0块
- 魔数用于验证文件系统合法性
- group_size 建议设置为 100（每组100个块号）

### 2.2 索引节点 (inode)

**作用**：存储文件/目录的元数据

| 字段 | 类型 | 大小(字节) | 说明 |
|------|------|-----------|------|
| ino | int | 4 | inode编号 |
| mode | int | 4 | 文件类型和权限（高4位类型，低9位权限） |
| uid | int | 4 | 所有者用户ID |
| size | int | 4 | 文件大小（字节） |
| atime | int | 4 | 访问时间戳 |
| mtime | int | 4 | 修改时间戳 |
| ctime | int | 4 | 创建时间戳 |
| block_count | int | 4 | 占用数据块数 |
| direct_blocks[10] | int | 40 | 直接索引块（一级索引） |

**文件类型定义**：
| mode高4位值 | 类型 |
|------------|------|
| 0x8000 | 普通文件 |
| 0x4000 | 目录 |
| 0x2000 | 符号链接 |

**权限定义**（低9位）：
- 所有者权限：位8-6
- 组权限：位5-3
- 其他用户权限：位2-0
- 每3位：r(读)=4, w(写)=2, x(执行)=1

**设计说明**：
- 采用一级索引，最多支持10个直接块
- 最大文件大小：10 × 4KB = 40KB
- inode总数固定，建议设置为100个

### 2.3 目录项 (dentry)

**作用**：表示目录中的一个条目

| 字段 | 类型 | 大小(字节) | 说明 |
|------|------|-----------|------|
| ino | int | 4 | 对应的inode编号 |
| name_len | int | 2 | 文件名长度 |
| name[252] | char | 252 | 文件名（最大252字符） |

**设计说明**：
- 每个目录项大小固定为256字节
- 每个目录块（4KB）可存储 4096/256 = 16 个目录项
- 每个目录默认包含 `.`（当前目录）和 `..`（父目录）

### 2.4 数据块 (block)

**作用**：存储文件数据或目录项

| 类型 | 说明 |
|------|------|
| DATA_BLOCK | 存储普通文件数据 |
| DIR_BLOCK | 存储目录项列表 |
| FREE_BLOCK | 空闲块 |
| INODE_BLOCK | 存储inode表 |

**设计说明**：
- 块大小固定为4096字节（4KB）
- inode表占用若干连续块
- 数据区从inode表之后开始

## 三、空间管理

### 3.1 成组链接法 (Group Linking)

数据块使用成组链接法 ：因为数据块数量可能很大，成组链接法可以节省空间，不需要为每个块都分配一个位图位。

**设计思路**：将空闲块分成若干组，每组包含若干块号，最后一块存储下一组的块号

**数据结构**：
```
┌──────────────────────────────────────────────┐
│  超级块: free_list_head = 第100块            │
└──────────────────────────────────────────────┘
                      │
                      ▼
┌──────────────────────────────────────────────┐
│  第100块 (空闲块组)                          │
│  ┌──────────────────────────────────────┐    │
│  │ 块号: 50, 51, 52, ..., 98, 99        │    │
│  │ next_group = 第40块                   │    │
│  └──────────────────────────────────────┘    │
└──────────────────────────────────────────────┘
                      │
                      ▼
┌──────────────────────────────────────────────┐
│  第40块 (空闲块组)                           │
│  ┌──────────────────────────────────────┐    │
│  │ 块号: 10, 11, 12, ..., 38, 39        │    │
│  │ next_group = 0 (结束标记)              │    │
│  └──────────────────────────────────────┘    │
└──────────────────────────────────────────────┘
```

**每组结构**（4KB块内）：
| 字段 | 类型 | 大小(字节) | 说明 |
|------|------|-----------|------|
| block_nums[1023] | int | 4092 | 本组合法块号（1023个） |
| next_group | int | 4 | 下一组所在块号（0表示结束） |

**分配算法**：
1. 从当前组取出一个块号
2. 如果当前组为空，读取next_group指向的块作为新的当前组
3. 更新super_block的free_list_head和free_blocks

**释放算法**：
1. 将释放的块号加入当前组
2. 如果当前组已满，将当前组写入新块，原块号作为新组的第一个元素
3. 更新super_block的free_list_head和free_blocks

---

### 3.2 位图法

inode 使用位图 ：因为 inode 数量有限（100个只需要13字节的位图），位图操作简单高效，查询和分配都很直接。


## 四、目录管理

### 4.1 多级目录结构

```
/ (根目录 inode=1)
├── home/ (inode=2)
│   ├── user1/ (inode=3)
│   │   ├── file1.txt (inode=4)
│   │   └── docs/ (inode=5)
│   │       └── report.pdf (inode=6)
│   └── user2/ (inode=7)
│       └── notes.txt (inode=8)
└── etc/ (inode=9)
    └── config.txt (inode=10)
```

### 4.2 目录项组织

每个目录块存储多个dentry结构：

```
目录块内容:
┌─────────────────────────────────────────────────────┐
│ dentry[0]: ino=3, name="."                         │
├─────────────────────────────────────────────────────┤
│ dentry[1]: ino=1, name=".."                        │
├─────────────────────────────────────────────────────┤
│ dentry[2]: ino=4, name="file1.txt"                 │
├─────────────────────────────────────────────────────┤
│ dentry[3]: ino=5, name="docs"                      │
├─────────────────────────────────────────────────────┤
│ ... (最多16个目录项)                                │
└─────────────────────────────────────────────────────┘
```

### 4.3 路径解析算法

**功能**：将路径字符串解析为对应的inode

```
输入: "/home/user1/docs/report.pdf"
输出: inode=6

步骤:
1. 从根目录(inode=1)开始
2. 解析路径为组件: ["home", "user1", "docs", "report.pdf"]
3. 逐级查找每个组件对应的目录项
4. 返回最终文件的inode
```

## 五、文件操作

### 5.1 文件创建 (create)

```
流程:
1. 分配空闲inode，初始化元数据
2. 创建目录项（在父目录中添加新条目）
3. 返回新文件的inode
```

### 5.2 文件删除 (remove)

```
流程:
1. 查找文件的inode
2. 释放所有数据块（归还到空闲链表）
3. 释放inode（归还到inode空闲链表）
4. 从父目录中删除对应的目录项
```

### 5.3 文件读取 (read)

```
流程:
1. 定位文件inode
2. 根据偏移量计算目标块号
3. 读取对应数据块内容
4. 返回数据
```

### 5.4 文件写入 (write)

```
流程:
1. 定位文件inode
2. 根据偏移量计算目标块号
3. 如果块不存在，分配新块并更新inode的direct_blocks
4. 写入数据块
5. 更新文件大小和修改时间
```

### 5.5 文件截断 (truncate)

```
流程:
1. 定位文件inode
2. 释放超出新大小的所有数据块
3. 更新文件大小
```

## 六、用户与权限

### 6.1 用户关联

每个文件/目录的inode包含uid字段，表示所有者

### 6.2 权限检查

**检查流程**：
1. 获取当前用户ID
2. 获取文件的uid和mode
3. 根据用户与文件的关系（所有者/组/其他）选择对应的权限位
4. 检查是否具备所需权限（读/写/执行）

## 七、磁盘布局

### 7.1 整体布局

| 块号 | 内容 | 说明 |
|------|------|------|
| 0 | 超级块 | 文件系统元信息 |
| 1-2 | inode表 | 存储所有inode（假设100个inode，每块50个） |
| 3 | 根目录块 | 根目录内容 |
| 4+ | 数据区 | 文件数据和子目录 |

### 7.2 空间计算示例

假设总块数 = 1000：
- 块0: 超级块
- 块1-2: inode表（2块）
- 块3: 根目录
- 块4-999: 数据区（996块）
- 最大文件数：100个inode
- 最大单个文件：10 × 4KB = 40KB

## 八、实现要点

### 8.1 内存映射

使用文件模拟磁盘，通过内存映射提高IO效率

### 8.2 缓存机制

- inode缓存：常用inode驻留内存
- 目录项缓存：最近访问的目录

### 8.3 事务性保证

- 写操作先写日志，再写数据
- 确保系统崩溃后可恢复

## 九、接口设计

```cpp
// 文件系统类
class FileSystem {
public:
    // 初始化与挂载
    bool mount(const std::string& diskPath);
    bool format(const std::string& diskPath, int totalBlocks);
    void unmount();
    
    // 文件操作
    int createFile(const std::string& path, int uid);
    bool deleteFile(const std::string& path);
    int readFile(int ino, char* buffer, int offset, int size);
    int writeFile(int ino, const char* buffer, int offset, int size);
    bool truncateFile(int ino, int newSize);
    
    // 目录操作
    int createDir(const std::string& path, int uid);
    bool deleteDir(const std::string& path);
    std::vector<Dentry> listDir(const std::string& path);
    
    // inode操作
    Inode getInode(int ino);
    bool updateInode(int ino, const Inode& inode);
    
    // 权限检查
    bool checkPermission(int ino, int uid, int permission);
    
    // 路径解析
    int resolvePath(const std::string& path);
};
```
